	\begin{enumerate}[label*=\arabic*.]
		\item \label{req.1} Requirement: The Raspberry Pi and the ESP32 must have a consistent, valid time obtained from the NTP server via the Raspberry Pi. \\
		Folge Requirements: \ref{req.1.1}, \ref{req.1.2}, \ref{req.1.3}, \ref{req.1.4}
		\begin{enumerate}[label*=\arabic*.]
			\item \label{req.1.1} Requirement: The Raspberry Pi must synchronise its time with the NTP server at start-up and every 60\,min.
			\item \label{req.1.2} Requirement: If the synchronisation fails three times in a row (one attempt every 30\,s), the Raspberry Pi must send an
			alert via Telegram and stop operation, i.e.\ it must neither send a schedule or time to the ESP32 nor send
			reminders.
			\item \label{req.1.3} Requirement: While operation is stopped, the Raspberry Pi must retry the synchronisation every 5\,min and resume normal
			operation once a valid time is available.
			\item \label{req.1.4} Requirement: The Raspberry Pi must transmit the current time to the ESP32 each time a Bluetooth connection is established.
		\end{enumerate}

		\item \label{req.2} Requirement: The HX711 sensor must provide predictable and plausible values. \\
		Folge Requirements: \ref{req.2.1}, \ref{req.2.2}, \ref{req.2.3}, \ref{req.2.4}, \ref{req.2.5}, \ref{req.2.6}, \ref{req.2.7}
		\begin{enumerate}[label*=\arabic*.]
			\item \label{req.2.1} Requirement: A measurement must be considered faulty if the HX711 does not deliver a value within 200\,ms.
			\item \label{req.2.2} Requirement: A measurement must be considered faulty if the raw value equals the minimum or maximum of the 24-bit range
			(\texttt{0x800000} or \texttt{0x7FFFFF}).
			\item \label{req.2.3} Requirement: A measurement must be considered faulty if the weight is below $-5$\,g or above 100\,g (capacity of the load cell).
			\item \label{req.2.4} Requirement: A measurement must be considered faulty if the weight changes by more than 5\,g outside an intake window.
			\item \label{req.2.5} Requirement: After a faulty measurement, the ESP32 must poll the sensor two more times. A sensor fault must only be
			assumed if both repeated measurements are also faulty.
			\item \label{req.2.6} Requirement: In case of a sensor fault, the ESP32 must suspend the dose evaluation, let the red LED flash and report the
			fault to the Raspberry Pi. The Raspberry Pi must then send an alert via Telegram.
			\item \label{req.2.7} Requirement: During a sensor fault, the ESP32 must check the sensor again every 10\,s and resume normal operation once
			valid values are delivered.
		\end{enumerate}

		\item \label{req.3} Requirement: The ESP32 must establish and maintain a Bluetooth connection to the Raspberry Pi. \\
		Folge Requirements: \ref{req.3.1}, \ref{req.3.2}, \ref{req.3.3}, \ref{req.3.4}, \ref{req.3.5}
		\begin{enumerate}[label*=\arabic*.]
			\item \label{req.3.1} Requirement: The ESP32 must make three attempts to establish the connection, 5\,s apart.
			\item \label{req.3.2} Requirement: If no connection can be established, the ESP32 must switch to autonomous mode: it must evaluate the intake
			with the last schedule stored in non-volatile memory, display the result via the RGB LED, buffer the results 
			and keep trying to reconnect in the background.
			\item \label{req.3.3} Requirement: If no valid schedule or time is available, the ESP32 must not perform any evaluation and must let the red LED
			flash.
			\item \label{req.3.4} Requirement: While connected, the ESP32 must send a heartbeat to the Raspberry Pi every 30\,s.
			\item \label{req.3.5} Requirement: If the Raspberry Pi receives no heartbeat for 2\,min, it must send an alert via Telegram and keep trying to
			reconnect.
		\end{enumerate}
	\end{enumerate}

\subsection{Security related requirements}

	\begin{enumerate}[label*=\arabic*., start=4]
		\item \label{req.4} Requirement: The communication between the ESP32 and the Raspberry Pi as well as the output of the system must not disclose or allow manipulation of health data. \\
		Folge Requirements: \ref{req.4.1}, \ref{req.4.2}, \ref{req.4.3}, \ref{req.4.4}, \ref{req.4.5}
		\begin{enumerate}[label*=\arabic*.]
			\item \label{req.4.1} Requirement: Each time a Bluetooth connection is established, the ESP32 and the Raspberry Pi must perform an ECDHE key exchange and agree on a new session key.
			\item \label{req.4.2} Requirement: All messages between the ESP32 and the Raspberry Pi must be encrypted and authenticated with AES-GCM using the session key. Messages with an invalid authentication tag must be discarded.
			\item \label{req.4.3} Requirement: Every message must carry a sequence number. Messages whose sequence number is not greater than that of the last accepted message must be discarded.
			\item \label{req.4.4} Requirement: Log messages must not contain any health data (intake times, doses, weights).
			\item \label{req.4.5} Requirement: Telegram messages must only be sent via HTTPS and must only contain the information necessary for the reminder or warning.
		\end{enumerate}
	\end{enumerate}

\subsection{Requirements with no influence on Safety and Security}

	\begin{enumerate}[label*=\arabic*., start=5]
		\item \label{req.5} Requirement: The ESP32 and the Raspberry Pi must output status messages (start-up, connection state, faults) via the log output. \\
		Folge Requirements: \ref{req.5.1}, \ref{req.5.2}, \ref{req.5.3}, \ref{req.5.4}
		\begin{enumerate}[label*=\arabic*.]
			\item \label{req.5.1} Requirement: The ESP32 must output its log messages via the serial interface (USB/UART) using the ESP-IDF logging functions. The Raspberry Pi must output its log messages on the terminal. Log messages are not stored permanently.
			\item \label{req.5.2} Requirement: Every log message must contain a timestamp, the name of the module and a log level (error, warning, info).
			\item \label{req.5.3} Requirement: At program start, the ESP32 and the Raspberry Pi must output a start-up message containing the software version.
			\item \label{req.5.4} Requirement: Logging must run in the thread with the lowest priority (see Table~\ref{tab:prio}) and must not block other threads. If the log output fails, operation must continue without logging.
		\end{enumerate}

		\item \label{req.6} Requirement: The source code must be maintainable and traceable. \\
		Folge Requirements: \ref{req.6.1}, \ref{req.6.2}
		\begin{enumerate}[label*=\arabic*.]
			\item \label{req.6.1} Requirement: The software of both devices must be written in C according to the MISRA C guidelines.
			\item \label{req.6.2} Requirement: The source code and this design document must be managed in the shared Git repository of the group.
		\end{enumerate}
	\end{enumerate}
